## 2. Robustness and adaptation

Executable tests (`backend/tests/`, 54 passing) cover:
- **Language:** paraphrase, negation ("it doesn't stop on its own" is recorded as a *rejected* idea, not a held one), abstention, and readings that contradict themselves (downgraded and flagged).
- **Code and explanation disagreeing:** correct code with a wrong explanation (*reasoning gap*), wrong code with a right explanation (counted as evidence that disagrees), and syntax errors unrelated to the concept (routed to *debugging*, never to a misconception).
- **Missing evidence:** no submission, no explanation, or explanation not analysed. Each leads to *insufficient evidence* or *reasoning unconfirmed*, never to a guess.
- **Different recursion problems:** the final verifier set uses `countdown` and `repeat_text`. Validator traps use `str_len`, `rev`, `count_x` and `triangle`.
- **Bad AI-generated activities:** reused problem, invalid JSON, no smallest-input test, imports, and a "misconception" version that actually passes. All are rejected before the sandbox stage or by it, and an unvalidated check cannot be approved.
- **Repeated requests:** duplicate drafts, approvals and executions create nothing new.
- **Provider failures:** timeouts, malformed output, truncation, refusal, an exhausted call budget, and a missing provider. Each is recorded per submission. Nothing silently falls back to rules when `ATHAR_ANALYZER=llm`.

## 3. Evaluation and iteration

- **Three splits with clear status:**
  - **dev** (generated, optimistic for rules)
  - **held-out** (still unseen for rules, probes and the verifier, but it informed the AI prompt, so it no longer counts as unseen for the AI reader, and this is disclosed)
  - **final** (unseen by everything)
- **Baselines:** "any failing test" for code, "always met" for explanations, and a tests-only ablation for planning.
- **Every percentage shows its count.** Per-case outputs and validation notes are saved in `backend/evals/results/*.json`.
- **Regression tracking:** the previous run's results are kept as `*.prev.json`, and the report shows the differences.
- **One harness bug found and fixed:** dev items were all validated against a single misconception. Committed with the fix, `cc7085f`.

## 4. Technical judgment and creativity

See [ARCHITECTURE.md](ARCHITECTURE.md) → *Design decisions*. In short:
- **An LLM only where language must be understood.** Reading student reasoning needs it; the rule reader's collapse on the final set (F1 12%) shows why.
- **Deterministic code execution, validation, diagnosis and verification.** These decide what happens to students, so they must be inspectable and repeatable.
- **The distinctive part: misconception → a validated new check.** A follow-up check (authored, or proposed by AI) is released only if correct code passes it *and* code holding the misconception fails it in the predicted way.
- **No multi-agent framework.** One stateful workflow plus focused model calls is enough here, and easier to verify.

## 5. Engineering quality

- **Module boundaries:**
  - `grading/` (sandbox, evidence rules)
  - `ai/` (provider, LLM reader, rule reader, reader choice)
  - `interventions/` (planning, service, validation, generation, verifier)
  - `insights.py`
  - `api/`
- **Persisted state for every step**, an audit trail for consequential actions, and roles and ownership enforced on the server.
- **Reproducible:**
  - `athar.cli reset --grade` restores the demo
  - `pytest` runs 54 tests
  - `evals.run` regenerates the report
  - the frontend has `npm run typecheck` and `npm run build`
- **Secrets stay in `backend/.env`** (git-ignored) and never reach the browser.

## Honest disclosures

- **Demo data favours the rule reader.** The synthetic class's explanations come from the same templates the rule reader was written from, so in-app explanation insights look cleaner than the reader's real ability. Compare dev 106/114 with final 14/36 on C3.
- **Simulated classmates** use short generic explanations and the check's own reference and misconception solutions. Their outcomes are computed by the verifier, but the inputs are not realistic student work.
- **The landing page** shows the most striking computed insight from the class.
- **Not implemented:** live AI evaluation (no credentials), material upload and retrieval, voice, LMS integration, real authentication.
