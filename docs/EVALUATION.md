## What is measured

| Suite | Question | Ground truth |
|---|---|---|
| Code grading | Do sandboxed tests and probes score the base-case criterion correctly and name the right misconception? | Instructor labels per program |
| Explanation reading | Does a reader find the misconception in written reasoning, and say *unclear* when the reasoning is too thin? | Instructor labels per explanation |
| Variant validation | Does the validator accept only follow-up items that genuinely separate correct code from the misconception? | Instructor labels per item |
| Verification | Does the verifier reach the outcome an instructor would (demonstrated / still developing / insufficient evidence)? | Instructor labels per attempt |
| System | Approval gates, permissions, idempotent execution, persistence, outage handling, fabricated-quote rejection | Executable pytest checks |

## Reading these results

- Dev numbers for the rule baseline are optimistic by construction: its phrase lists were written from the dev templates. The held-out column is the one to trust.
- Code grading is deterministic, so it is stable across runs. Explanation reading is where generalisation is hard, and it is the part designed to be taken over by an LLM when credentials exist.
- The verifier only reaches *demonstrated* when tests and reasoning agree, so a weak reasoning reader pushes outcomes towards *insufficient evidence* or *still developing*, never towards false success.
