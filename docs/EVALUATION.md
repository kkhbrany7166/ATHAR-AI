## Reading these results

- **Final** is the reported generalisation result. **Held-out** stays unseen for the rule baseline, probes and verifier, but it informed the LLM prompt design, so LLM numbers on it are development numbers.
- Rule-baseline numbers on **dev** are optimistic by construction: its phrase lists were written from the dev templates.
- Code execution, validation and verification rules are deterministic, so they are stable across runs. Explanation reading is the hard, open-ended part, and the part an LLM is for.
- The verifier says *demonstrated* only when tests and reasoning agree, so a weak reader pushes outcomes towards *insufficient evidence*, never towards false success.
